原版与蓝围巾只保留 b10 的 `click_reaction`（摸摸头）和 `play`（玩一会儿）。其他动作恢复 v0.9 原始帧、停留时间与循环设置；右键不恢复动画，仅使用现有菜单。原版和蓝围巾预览也恢复 v0.9。`action-policy-v010b11.json` 记录发布标签来源、旧动作声明与资源哈希，以及保留动作逐帧 RGBA 哈希和时序。

`python -m scripts.build_companion_motion --gestures-only` 只替换原版和蓝围巾的 32 帧招呼、23 帧懒腰及停留时间。图集采用无损 PNG，其他 637 帧逐帧像素保持不变；帧数、解码、包体和 20fps 限制不变。历史原画继续保留用于追溯，下面各轮记录描述当时方案；目前播放以 b10 为准。动作预览见 [b10 说明](../../docs/gesture-repair-b10.md)。

## v0.10.0b3 完整角色原画（2026-10-09）

v0.10.0b2 的肩部实体接触检查只能排除脱离，不能证明造型自然。该轮素材仍有头部下缘截断与胸前贴片感，已停止用于原版与蓝围巾的站立动作。

使用 Codex 内置 imagegen，以原版 `ferret_atlas_2x.png` 为角色身份参考，生成 `coherent-neutral-v3.png`：完整前视站姿、自然短颈和圆肩、两只前爪自然分开垂落、白色毛皮与深灰尾巴、真实透明背景；明确禁止分离头部、横向切线、交叉前爪和肩部帽状边缘。随后分别生成仅改变眼睛的 `coherent-half-v3.png` 和 `coherent-closed-v3.png`。采用内置工具，未使用外部 API CLI。

`scripts/companion_mesh.py` 只将半闭眼与闭眼稿的两个眼部窗口合入中性完整原画，其余轮廓、脖颈和身体像素全部保留中性原画。统一源矩形 `(326,170)-(1100,1158)` 配准到 384 画布上的 `(76,32,248,316)`。所有 16px 网格共享边界顶点和位移场，构建时烘焙连续变形，运行时仍播放普通透明图集。此方式不是 Live2D/Cubism 模型，也不声明具备其能力。

睡眠与阅读继续使用原分层稿中本来就完整绘制的整只动物姿态，不使用分离身体部件。旧 `rig-parts.png` 保留用于来源追溯及这两个完整姿态。应用图标为项目内 SVG 矢量设计，以眼睛为主体，托盘保持恢复的 v0.9.0 PNG。


v0.10.0b4 依据实际任务栏反馈，将 SVG 图标配色改为浅灰绿与低反差绿瞳；角色原画和动作不变。

## v0.10.0b6 完整动作姿态（2026-10-09）

采用 Codex 内置 imagegen 的编辑模式，以 `coherent-neutral-v3.png` 为身份参考生成两张透明动作原画，未使用外部 API CLI：

- `greeting-keyposes-v4.png`（1536×1024，3×2）：完整角色的中性、前爪抬到胸口、露肉垫、向外招手、闭眼微笑和放下前爪。提示要求相同画风、脸型、大小和脚底基线，完整肩颈与四肢连接，白毛、淡蓝阴影、粉色耳朵和深灰尾巴；实际采用的招手稿含三笔小幅挥手线。
- `walk-keyposes-v4.png`（1536×1024，2×2）：同一白鼬改为自然四脚轻跑，头朝右、尾巴在左，四张接触/迈步姿态。提示强调近侧前爪从前伸转为后收、四足交替、相同镜头与角色比例、透明背景、无地面和阴影。先前的人形双脚行走候选因面部跳变或步态不清晰未采用，留在本地设计工作目录。

`scripts/companion_keyposes.py` 使用人工检查过的中心轴、脚底基线和统一比例配准完整姿态；不从图中切下胳膊或脖子。移动最终镜像为朝左，以匹配现有播放器向右移动时镜像的约定。蓝围巾为原生路径绘制，站立与四脚姿态使用不同服装位置。

站立中性原画的配准 x 从 76 调整为 98，使身体中心轴处于画布中心 x=192；全部完成姿态以脚底为中心统一缩小到 95%，给抬头、跳跃和摆尾留出透明边缘。中等幅度的头部、尾巴和拖拽跟随仍使用共享顶点网格；小跳、回弹和伸懒腰使用完整身体的脚底基准变换。大幅抬爪不通过局部拉伸制作。动作编排的分阶段曲线见 `scripts/companion_mesh.py`。

可重建入口仍为 `python -m scripts.build_companion_motion`。原版 218 帧声明、围巾 60 帧；每个长动作先统一量化，再按不超过 25 个单元分页。运行时仍为普通透明 PNG 图集，未使用或声称为 Live2D。图标保持 v0.9.0 原版。

所采用的两次内置生成工具提示词与参考图片记录保存在 `motion-prompts-v4.json`。


## v0.10.0b7 完整注视姿态（2026-10-09）

`gaze-keyposes-v5.png` 是内置 imagegen 的编辑结果（1254×1254，3×3 透明画布）。参考中性原画生成，九个方向顺序为：左上、上、右上、左、正面、右、左下、下、右下。完整角色只改变实际头部朝向和跟随的颈部，不拆分前爪，不通过整体图像旋转制造方向。输入布局与完整提示词记录见 `gaze-prompts-v5.json`。

`companion_keyposes.py` 将每个 418×418 单元按共同身体中心 x=209、脚底 y=393、比例 316/370 配准到现有画布。九个姿态共享同一尺度，没有按各自包围盒拉伸。运行时以单帧姿态表达持续注视，普通待机、招呼、跳跃和移动保留 b6 动作；蓝围巾同样有九个完整注视姿态，整套仍限制在 60 帧。原版共 200 帧。可重建入口不变。

借鉴范围是本机 Codex 的精灵图组织、姿势语义和右键交互；Codex 角色图片和应用代码均不进入源码交付或软件包。


## v0.10.0b8 连续动作与姿态（2026-10-09）

内置 imagegen 编辑工具新增完整伸懒腰姿态 stretch-sequence-v8.png，以及参考本仓库 v0.9 原版自然行走比例重画的四张完整小步走姿态 walk-keyposes-v6.png。每张原画包含整只动物，头、颈、肩膀、四肢保持相连；提示词与参考记录见 motion-prompts-v6.json。招呼复用 v4 的一张完整抬爪姿态，挥爪期间固定表情与身体，原版的待机、眨眼、小跳、摆尾和玩球继续复用。

companion_pose_morph.py 在构建时沿对应点路径重采样最近的完整原画，避免两张原画交叉淡化产生双眼和重影。动作继续烘焙为透明 PNG，不切出独立胳膊或颈部，也不增加运行时图像处理依赖。注视使用同一完整中性图的共享连续网格制作 25 个姿态；身体和脚底固定，头部与眼部作小幅朝向调整，运行时对鼠标目标缓动并使用边界滞回。

原版共 256 帧，蓝围巾 143 帧；单造型上限改为 160，原有单动作 60、基础 256、造型合计 512、包体 64MiB、20fps 等限制继续保留。其他 12 套造型和 v0.9.0 原版图标未改动。重建入口仍为 python -m scripts.build_companion_motion。

`stretch-keypose-v6.png` 和 `stretch-keypose-v7.png` 保留为早期比例修改和来源参考；最终播放使用 `stretch-sequence-v8.png` 的六张完整过程姿态。完整编辑提示词与参考文件记录在 `motion-prompts-v6.json`。统一比例和脚底基线登记见 `scripts/companion_keyposes.py`。

用户指出旧懒腰中间帧脸和躯干变形后，完全撤掉该动作的网格插值。最终 `stretch-sequence-v8.png` 有六张完整抬爪过程原画，按节奏逐帧抬起、停顿、回落；没有对脸、躯干或下半身做形变。原版和围巾均沿用该组完整姿态。
